# 商场清洁机器人运营管理系统 · 需求说明

> WorkItem：wi-t1000005 ｜ 阶段：requirements
> 来源标注约定：【用户提出】= 用户原始请求明确表达；【已确认】= 既有基线已确认；【推荐基线】= 为闭合核心目标必需、且安全可逆可观察的最小基线；【未规定】= 用户未明确且不影响核心验收。

## 1. 目标

开发清洁任务编排与实时运营看板。运营人员按商场楼层和区域配置清洁计划，指定机器人、作业时间和清洁模式；机器人执行时，看板实时展示当前位置、任务进度、已清洁面积和异常状态；完成后生成作业报告。【用户提出】

本需求以一条完整演示流程作为验收主线：创建晚间清洁计划 → 分配机器人 → 查看实时进度 → 完成并查看报告。【用户提出】

## 2. 角色

- **运营人员**：本需求唯一明确的使用者。负责配置清洁计划、分配机器人、查看实时进度与作业报告。【用户提出】

未提及其他角色、受众或权限分级；不自行推断。

## 3. 核心实体

- **清洁计划**：按楼层和区域配置，包含作业时间、清洁模式，是清洁任务编排的对象。【用户提出】
- **机器人**：被分配到计划并执行清洁作业的资源。【用户提出（"指定机器人 / 分配机器人"）】
- **执行与看板数据**：机器人执行过程中产生当前位置、任务进度、已清洁面积、异常状态。【用户提出】
- **作业报告**：任务完成后生成，记录该次作业结果。【用户提出】

## 4. 端到端旅程（清洁计划全流程，完整说明一次）

1. 运营人员创建晚间清洁计划：选择楼层和区域，设定作业时间，选择清洁模式。【用户提出】
2. 运营人员为该计划分配机器人。【用户提出】
3. 机器人开始执行，运营人员在实时看板查看当前位置、任务进度、已清洁面积、异常状态。【用户提出】
4. 任务完成，系统生成作业报告，运营人员查看报告。【用户提出】

后续模块需求仅描述各步骤的具体行为与边界，不重复展开旅程。

## 5. 模块需求

### 5.1 清洁计划配置
- 运营人员可创建清洁计划，创建时需指定：楼层、区域、作业时间、清洁模式。【用户提出】
- 计划创建成功后可被读回，且字段与输入一致（不依赖刷新/重开/重启后的持久化承诺即可在读回时观察到）。【已确认（CRUD 读回基线）】
- 清洁模式作为计划的可配置属性；其具体可选取值未规定，不预设模式清单。【未规定】

### 5.2 机器人分配
- 运营人员可为已创建的计划分配机器人；创建计划与分配机器人是流程中两个可区分的步骤。【用户提出（验收流程将二者分为两步）】
- 分配成功后可读回计划与机器人的关联。【已确认（读回基线）】
- 一次计划分配的机器人数量未规定；按演示流程以"为该计划分配机器人（至少一个）"表述，不推断单/多机器人策略。【未规定】

### 5.3 执行与实时看板
- 机器人执行期间，看板实时展示四项数据：当前位置、任务进度、已清洁面积、异常状态。【用户提出】
- 看板数据随机器人执行实时更新（"实时展示"为用户明确要求）；不指定轮询/推送等实现技术。【用户提出（实时性）；技术选型未规定】
- 当前位置以楼层/区域表达，与计划的楼层/区域维度保持一致。【推荐基线（最小一致的可观察表达）】
- 任务进度、已清洁面积以可观察的数值/状态展示；其具体计量单位或百分比口径未规定。【未规定】
- 异常状态作为看板的一项展示内容；异常的具体分类与触发条件未规定，不预设异常类型清单。【未规定】
- 执行启动时机：分配机器人后任务进入执行状态、看板开始展示实时数据。【推荐基线（使"查看实时进度"可观察的最小闭环）】作业时间作为计划的配置项保留【用户提出】；是否按作业时间自动调度执行未规定，不作为本次验收前提。【未规定】

### 5.4 作业报告
- 任务完成后系统生成作业报告，运营人员可查看。【用户提出】
- 报告内容为对该任务执行结果的汇总落档，至少包含执行期间已在看板展示的可观察结果：已清洁面积、任务进度、异常记录。【推荐基线（使"查看报告"具备可观察内容的最小闭合）】报告版式、字段顺序、是否可导出未规定。【未规定】

### 5.5 机器人来源（演示前提）
- "分配机器人"步骤需要一个可选择的机器人清单。系统内是否提供机器人档案管理（增删改查）未规定，用户未作要求；演示以"存在可供分配的机器人"为前提。【未规定 / 演示前提】

## 6. 入口与载体
- 全部交互入口按"用户界面"理解：运营人员通过界面完成创建计划、分配机器人、查看实时进度与报告。此表述仅表示交互入口，不指定页面布局，也不推断 Web、桌面端、移动端或设备适配。【用户提出（创建/查看等人机操作）；载体未规定】

## 7. 验收场景

以下 AC 覆盖用户提出的核心目标与验收主线四步。四步属于同一连续演示流程，共享流程组，可依序连续验证；每一步的结果与验证时机相互独立，故分别成条。

### AC-01：运营人员可创建晚间清洁计划
- 验收条件：运营人员可按楼层、区域、作业时间、清洁模式创建清洁计划，创建后可读回且字段与输入一致。
- 入口类型：用户界面
- 验证动作：以运营人员身份创建一条晚间清洁计划，选择某楼层和区域，设定作业时间，选择清洁模式并保存；随后重新打开该计划查看。
- 预期结果：计划保存成功；重新打开时楼层、区域、作业时间、清洁模式均与输入一致。
- 证据类型：interaction, runtime-render
- 共享流程组：晚间清洁演示流程

### AC-02：运营人员可为计划分配机器人
- 验收条件：运营人员可为已创建的计划分配机器人，分配后可读回计划与机器人的关联。
- 入口类型：用户界面
- 验证动作：在 AC-01 创建的计划上执行"分配机器人"，从机器人清单中选择一个机器人并确认；随后查看该计划的机器人信息。
- 预期结果：分配成功；该计划显示已关联所选机器人。
- 证据类型：interaction
- 共享流程组：晚间清洁演示流程

### AC-03：执行期间看板实时展示进度
- 验收条件：机器人执行期间，看板实时展示当前位置、任务进度、已清洁面积和异常状态，并随执行实时更新。
- 入口类型：用户界面
- 验证动作：在 AC-02 分配机器人后，打开该计划的实时看板，观察机器人执行过程中看板数据的变化。
- 预期结果：看板实时显示机器人当前位置（楼层/区域）、任务进度、已清洁面积；出现异常时展示异常状态；上述数据随执行推进而更新。
- 证据类型：runtime-render, interaction
- 共享流程组：晚间清洁演示流程

### AC-04：完成后生成并可查看作业报告
- 验收条件：任务完成后系统生成作业报告，运营人员可查看报告内容。
- 入口类型：用户界面
- 验证动作：在 AC-03 的任务执行完成后，打开该任务的作业报告查看。
- 预期结果：报告已生成，包含该任务的执行结果（已清洁面积、任务进度、异常记录）。
- 证据类型：runtime-render
- 共享流程组：晚间清洁演示流程

## 8. 未规定事项（不影响核心验收，本次不展开）

清洁模式具体取值、异常具体分类、任务进度计量口径、作业报告版式与导出、机器人档案管理、单/多机器人分配策略、是否按作业时间自动调度、产品载体（Web/桌面/移动）均未规定。入口统一按"用户界面"理解，不代表指定页面布局或产品载体。
