# 清洁机器人运营管理系统需求

> 来源标注：【用户】= 用户明确提出；【推荐】= 为闭合核心目标补充的最小推荐基线（保守、可观察）；其余未标注的下游决策点见"未规定事项"。

## 1. 目标

面向大型购物中心、商业综合体【用户】，提供清洁机器人智能运营管理系统【用户】：

- 实现多商场、多楼层、多机器人统一管理【用户】；
- 提供可视化监控、智能任务调度、设备运维、数据分析四大核心能力【用户】；
- 业务价值：提升商场清洁效率，降低人工管理成本【用户】。

本系统管理与调度的对象为清洁机器人；系统向机器人下达任务、机器人向系统上报运行状态，是该目标内含的必要数据流【推荐：仅作为产品行为边界，不指定通信技术与协议】。

## 2. 管理对象与层级

| 对象 | 说明 | 归属关系 |
| --- | --- | --- |
| 商场 | 运营管理的顶层对象，系统同时管理多个商场【用户】 | — |
| 楼层 | 每个商场包含一个或多个楼层【用户】 | 归属商场 |
| 机器人 | 每台清洁机器人归属唯一楼层，进而归属唯一商场【推荐】 | 归属楼层 |

- 每台机器人具有可识别的基本信息（名称/编号）【推荐】。

## 3. 核心旅程（端到端）

1. 登记组织：创建商场、楼层，登记机器人，形成统一管理的层级组织。
2. 日常监控：通过可视化界面查看各机器人运行状态与所在楼层。
3. 任务调度：创建并下达清洁任务，系统分配机器人执行，跟踪至完成。
4. 运维处理：机器人异常或需维护时登记运维事件，处理后关闭。
5. 数据分析：查看基于运营数据的统计与分析结果。

## 4. 模块需求

### M1 组织与设备管理
- 商场、楼层、机器人的登记（创建）与查看；登记成功后可通过列表/详情读回。
- 按商场→楼层→机器人层级浏览全部对象，实现跨商场的统一查看。
- 对象基本信息的更新（如名称、机器人楼层归属调整）【推荐】。

### M2 可视化监控
- 以可视化形式展示每台机器人当前运行状态及其所在商场/楼层。
- 机器人状态数据可更新，状态变化可在界面上反映。
- 机器人运行状态至少可区分"执行任务中"与"异常"【推荐】；完整状态枚举未规定。
- 可视化具体形式（地图/列表/卡片等）与数据刷新频率未规定。

### M3 智能任务调度
- 用户创建清洁任务并下达，任务至少关联目标楼层（或楼层内机器人范围）。
- 系统为任务分配机器人并推进执行；任务状态可跟踪，至少可区分待执行、执行中、已完成【推荐】。
- 任务完成后，任务记录可读回，并关联所涉楼层与执行机器人。
- "智能"的具体调度策略（如路径规划、任务优先级、自动排班）未规定，不属于本次验收依据。

### M4 设备运维
- 机器人故障或维护需求可登记为运维事件，事件与具体机器人关联。
- 运维事件可处理并关闭；事件状态至少可区分未处理/已处理【推荐】。
- 运维历史记录可查。

### M5 数据分析
- 提供基于系统内运营数据的统计与分析视图，数据范围至少覆盖任务执行、机器人运行、运维记录【推荐】。
- 统计结果与系统内对应实际记录一致，不展示与记录不符的虚构数据。
- 具体分析指标与图表形式未规定。

## 5. 关键规则

- 层级唯一归属：每台机器人归属唯一楼层，每楼层归属唯一商场【推荐】。
- 任务执行对象为机器人，任务与楼层/机器人关联【推荐】。
- 监控、调度、运维、分析围绕同一机器人对象体系，数据同源【推荐】。

## 6. 未规定事项

以下事项用户未明确规定，实现阶段可自行决策，验收不以其为依据：

- 智能调度的具体策略与算法；
- 机器人状态、任务状态、运维事件的完整状态枚举；
- 可视化具体形式与数据刷新频率；
- 用户角色划分与权限体系（用户未提出，不设角色）；
- 部署平台、产品载体（Web/桌面/移动）与技术选型；
- 数据长期持久化周期（验收仅要求写入后可通过相应读取行为读回）。

## 7. 验收场景

### AC-01：多商场多楼层多机器人统一登记与层级管理
- 验收条件：用户可创建商场、楼层与机器人，形成商场→楼层→机器人的层级组织，并按层级统一查看与读回。
- 入口类型：用户界面
- 验证动作：创建商场 A；在商场 A 下创建楼层 F1；在 F1 下登记机器人 R1；另创建商场 B，登记其楼层 F2 与机器人 R2；随后从商场列表逐层浏览，并打开各对象详情。
- 预期结果：商场 A、B 均出现在商场列表并可进入；从商场 A 可浏览 F1，F1 下可见机器人 R1；商场 B 下 F2 与 R2 同样可按层级读回；各对象登记的信息（名称/编号等）可通过列表与详情读回，与登记内容一致。
- 证据类型：interaction

### AC-02：机器人运行状态可视化监控
- 验收条件：用户可通过可视化界面查看每台机器人的当前运行状态与所在商场/楼层，机器人状态变化可在界面上反映。
- 入口类型：用户界面
- 验证动作：在已登记多台机器人的情况下打开监控界面，查看各机器人的状态与位置展示；使其中一台机器人状态发生变化（如通过下达清洁任务使其进入执行中，或触发异常），回到监控界面查看该机器人。
- 预期结果：监控界面以可视化形式同时展示多台机器人及其状态与归属楼层；发生变化的机器人，其状态在界面上更新展示（如由空闲/待命变为执行任务中或异常）。
- 证据类型：runtime-render, interaction

### AC-03：清洁任务创建、调度与执行跟踪
- 验收条件：用户可创建并下达清洁任务，系统为其分配机器人执行，任务状态可跟踪至完成，完成后任务记录可读回。
- 入口类型：用户界面
- 验证动作：创建一个指定楼层的清洁任务并下达；查看任务列表与任务详情中的分配结果与状态；推进任务至完成后再次查看任务记录。
- 预期结果：任务创建后由系统分配机器人并进入执行；任务状态在系统中依次可见（待执行→执行中→已完成）；完成的任务记录中可读回所关联的楼层与执行机器人。
- 证据类型：interaction, runtime-render

### AC-04：机器人运维事件登记与处理
- 验收条件：用户可为机器人登记运维事件（故障/维护），处理后事件关闭，处理结果与运维历史可查。
- 入口类型：用户界面
- 验证动作：为一台机器人登记一次故障或维护事件；对该事件执行处理并关闭；查看该机器人的运维记录列表。
- 预期结果：新事件出现在运维记录中并与该机器人关联；处理后事件状态更新为已处理/已关闭；历史记录保持可读回。
- 证据类型：interaction

### AC-05：运营数据统计分析
- 验收条件：用户可查看基于系统内运营数据汇总的统计与分析结果，统计内容与实际运营记录一致。
- 入口类型：用户界面
- 验证动作：在系统内已产生若干任务执行与运维记录后，打开数据分析界面，读取统计结果并与系统内对应记录对照。
- 预期结果：界面展示基于运营数据汇总的统计，覆盖任务执行情况与机器人运行/运维情况；统计数值与系统内对应记录一致，无虚构数据。
- 证据类型：runtime-render, interaction
